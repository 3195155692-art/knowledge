**命名规则**

1. 采用"两位数字编号 + 空格 + 中文名"的格式，编号保证目录排序稳定；
2. 不添加英文副标题（英文名写在文首 aliases 与正文首行）；
3. **双链名称必须与文件名（去掉 `.md`）完全一致**，否则 Obsidian 图谱会断链；
4. 新增篇目请续用未占用的编号，不要插入到已有编号中。

## 二、统一体例（每篇都按此骨架）

| # | 章节 | 写什么 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 一句话定位 / 能回答什么问题 | 这项技术回答什么问题、不适合回答什么、典型样本与周期成本 | 30 秒内判断"我这批样本该不该做" |
| 2 | 基本原理 | 只讲"为什么能量出来"（化学/物理/生物学原理），**算法与建模细节从略** | 能向同事解释信号如何变成数字 |
| 3 | 技术方案怎么选 | 主流平台对照表 + 选择原则 | 给定样本与预算能选出方案 |
| 4 | 实验设计与样本要求 | 样本类型与保存、重复数与批次、对照、伦理；附"送检前必须问清楚的五个问题" | 能自己写出送检单并识别设计错误 |
| 5 | 数据产出与文件格式 | 原始 → 中间 → 结果格式及其用途 | 拿到数据知道每个文件是什么 |
| 6 | 标准分析流程 | 每步：目的 / 常用工具 / 关键点；附关键参数怎么读 | 能复现一条标准流程 |
| 7 | 质量控制指标 | 指标阈值表 + 异常含义与排查 | 能判断一批数据可用/不可用 |
| 8 | 结果怎么读（临床视角） | 报告里哪几个数字决定结论、常见误读 | 能读懂第三方报告并识别过度解读 |
| 9 | 临床应用场景 | 分场景叙述，每场景有指南或里程碑文献支撑 | 知道这项技术临床真实用在哪 |
| 10 | 局限与常见陷阱 | 每个坑写"错在哪 + 怎么避免" | 投稿前能自查 |
| 11 | 工具与资源速查 | 软件、数据库、平台、R/Python 包 | 能直接照着用 |
| 12 | 权威出处 | 按 A/B/C/D 四级分类列出 | 每个关键论断可溯源 |
| 13 | 术语速查 | 中英对照 + 一句话解释 | 非本领域读者能读懂 |
| 14 | 关联知识 | Obsidian 双链，名称与文件名严格一致 | 图谱无断链 |

**例外说明**：速查类（12）、规范类（99）、入口类（00）三篇按内容需要组织，不强制套用全部 14 节。

**实操篇（14–19）的额外要求**

| 要求 | 说明 |
| --- | --- |
| 给出可运行骨架 | 命令或代码可直接改用，变量名与路径写成占位符 |
| 标出参数含义 | 关键参数必须解释"为什么这么设" |
| 注明版本敏感性 | 明确哪些版本差异会导致结果变化 |
| 列出常见报错 | 每个流程至少给出 5 条常见报错与排查方向 |
| 附自查清单 | 交付前逐条核对 |

## 三、撰写原则

1. **面向临床、以应用为主**：每节结尾都要能回答"这对临床判断有什么用"。
2. **原理只保留影响判读的部分**：例如"深度不足为何检不出低丰度变异"必须写；"德布鲁因图如何构建"不必写。
3. **给出阈值与数字**：能写具体阈值就写具体阈值（如 Q30、FRiP、检测限），并注明适用条件与来源级别；避免"MUST 很高"这类无操作性的表述。
4. **区分证据强度**：明确标注"已进入指南/常规"、"前瞻性研究支持"、"仅有相关性证据"、"研究阶段"。这是本库区别于网络科普的关键。
5. **写清局限**：每篇必须有独立的局限与陷阱一节，不把局限藏在正文角落里。
6. **不夸大、不省略阴性面**：阴性结果的含义、假阳性来源、不可解释的情形都要写出来。

## 四、引用规范

### 4.1 出处分级

| 级别 | 类型 | 举例 |
| --- | --- | --- |
| **A 级** | 国际学会指南 / 共识 / 正式标准 | ACMG/AMP 变异解读标准、CPIC 药物基因组学指南、NCCN/ESMO 推荐、CLSI 标准、Metabolomics Society 报告标准、HUPO 的 MIAPE |
| **B 级** | 权威综述、里程碑原始论文、权威教科书 | Nature Reviews 系列综述、Cell/Nature/Science 主刊论文、领域标准教科书 |
| **C 级** | 方法学奠基文献 | DESeq2、limma、Seurat、MACS2、BWA 等方法的原始文献 |
| **D 级** | 官方文档与权威数据库 | GATK / Bioconductor / Illumina / 10x 官方文档；ENCODE、GEO、ClinVar、gnomAD、HMDB |

### 4.2 写法与格式

- 正文关键论断后标注来源级别，例如："组织混样导致的细胞比例变化常被误读为表达改变[B]"；
- 文末按"指南与共识 / 综述与经典文献 / 官方文档与数据库"三类集中列出；
- 每条包含：作者、标题、期刊（或出版方）、年份、卷期页码、DOI 或可访问链接；
- 数据库类按"名称 + 官方站点 + 访问日期"引用；
- 品牌或平台信息只在说明具体用法时引用其**官方技术文档**，并标明来源性质为厂商文档。

### 4.3 不采用

自媒体文章、来源不明的中文博客与二手转述、厂商宣传材料（官方技术文档除外）、无法核实出处的"专家意见"。

### 4.4 维护要求

1. 交付或修订前，**逐条核对引文能否打开、DOI 是否有效**；
2. 涉及临床决策的条目（指南、阈值、适应证）**每次修订都需重新核对最新版本**；
3. 数据库与指南的变化要在正文注明版本或年份，避免"结论过时但无人察觉"；
4. 修订后更新文首"更新日期"，重要改动可在文末加一行说明。

## 五、交叉链接规范

1. 双链格式统一为 `[[文件名]]`（如 `[[01 基因组学]]`），与文件名完全一致；
2. 每篇的"关联知识"一节至少链接 3 篇相关篇目，并给出一句话说明**为什么相关**；
3. 新增篇目后，需回到 `00 知识库总览` 与相关篇目补上互链；
4. 重命名文件时，必须同步修正全库所有指向它的双链。
