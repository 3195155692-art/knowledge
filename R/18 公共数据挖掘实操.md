# 公共数据挖掘实操

> **一句话定位**：用别人已经上传的数据做自己的研究——这是临床研究者**成本最低、见效最快**的路径。规范做法是"公共数据做发现、自有样本做验证"。
> 数据库资源清单见 [[12 公共数据库与资源速查]]；统计与报告要求见 [[11 临床研究设计与统计要点]]。

---

## 一、三条常用路线

| 路线 | 数据类型 | 典型用途 | 主要门槛 |
| --- | --- | --- | --- |
| **GEO** | 芯片、bulk RNA-seq、单细胞 | 找差异、找验证队列、做免疫浸润 | 样本分组与临床信息常需手工整理 |
| **TCGA / GDC** | 肿瘤多组学 + 临床随访 | 预后分析、分型、免疫浸润、突变关联 | 数据量巨大、临床字段需清洗 |
| **GTEx / CPTAC / MetaboLights 等** | 正常组织基线、蛋白组、代谢组 | 提供正常参照、跨组学验证 | 数据模型各异，处理方式不同 |

**先想清楚一件事**：这笔数据是用来**发现**还是用来**验证**？同一数据集不能既筛特征又验证特征。

---

## 二、下载前必须记录的信息

| 字段 | 例子 | 为什么必须记 |
| --- | --- | --- |
| 数据集编号 | GSE12345 / TCGA-BRCA | 论文与可复现性要求 |
| 平台 | GPL570 / GPL24676 | 决定预处理方法，跨平台不能直接合并 |
| 数据类型 | 芯片原始 CEL / RNA-seq counts / FPKM | 决定归一化与统计方法 |
| 样本量与分组 | 肿瘤 40、正常 12 | 决定统计功效 |
| 分组定义来源 | 原文、样本注释表、病理信息 | 标签错误会让全部结论作废 |
| 临床信息完整性 | 分期、生存时间、结局 | 缺随访就无法做预后分析 |
| 批次信息 | 芯片批次、中心、提取批次 | 无法校正时会与分组混杂 |

**操作建议**：每下载一个数据集，就在 `01_meta/` 下写一个 `dataset_xxx.md`，把上述字段与下载命令记进去。半年后你会感谢自己。

## 三、GEO 芯片数据流程（代码骨架）

```r
library(GEOquery); library(limma); library(sva); library(ggplot2)

## 1. 下载（series matrix 直接拿到已归一化矩阵；要重做预处理则下原始 CEL）
gset  <- getGEO("GSE12345", GSEMatrix = TRUE, getGPL = TRUE)[[1]]
expr  <- exprs(gset)                 # 已归一化矩阵
pdata <- pData(gset)                 # 样本信息（分组、临床字段常需手工核对）

## 2. 数值处理：log 转换（若尚未转换，按分布判断）
ex <- expr; qx <- as.numeric(quantile(ex, c(0, .25, .5, .75, .99, 1), na.rm = TRUE))
if (qx[6] > 100) ex <- log2(ex + 1)

## 3. 分组（务必逐一核对，不要按列顺序硬指定）
group <- factor(pdata$`disease state:ch1`, levels = c("normal", "tumor"))

## 4. 批次校正（先确认批次与分组是否混杂！）
mod <- model.matrix(~ group)
ex_corrected <- ComBat(ex, batch = pdata$batch, mod = mod)

## 5. 差异表达
design <- model.matrix(~ group)
fit <- eBayes(lmFit(ex_corrected, design))
deg <- topTable(fit, coef = 2, number = Inf, adjust.method = "BH")
write.csv(deg, "06_results/GSE12345_DEG.csv")
```

**要重做预处理时（拿原始 CEL 文件）**：用 `affy`/`oligo` 的 RMA 归一化，再走上述第 3 步之后。**必须在论文中写明用的是原始数据还是作者提供的矩阵**。

### 3.1 数据集选择与合并的注意点

- 多个数据集合并前先分别归一化，再校正批次；跨平台合并本身存在争议，**能分别分析就分别分析**；
- 报名的"外部队列验证"必须是**未参与建模**的独立数据集；
- 只用了作者提供的矩阵时，无法重做归一化，属于**不可控的预处理差异**，要在局限中说明。

## 四、TCGA / GDC 数据流程（代码骨架）

```r
library(TCGAbiolinks); library(SummarizedExperiment); library(dplyr)

## 1. 查询：RNA-seq 基因表达（STAR-Counts 更适合差异表达；FPKM 适合跨样本展示）
q <- GDCquery(project = "TCGA-LUAD",
              data.category = "Transcriptome Profiling",
              data.type = "Gene Expression Quantification",
              workflow.type = "STAR - Counts")
GDCdownload(q, files.per.chunk = 50)
se <- GDCprepare(q)

## 2. 表达矩阵与基因注释
mat <- assay(se, "unstranded")            # 计数矩阵
rowData(se)$gene_name[1:5]

## 3. 临床数据（字段名随版本变化，务必先查看再取）
clin <- GDCquery_clinic("TCGA-LUAD", type = "clinical")
clin <- clin |> transmute(barcode = submitter_id,
                          stage = ajcc_pathologic_stage,
                          os_time = days_to_death,
                          os_event = vital_status)

## 4. 突变数据（MAF）用于展示突变谱或做分组
maf_q <- GDCquery(project = "TCGA-LUAD",
                  data.category = "Simple Nucleotide Variation",
                  data.type = "Masked Somatic Mutation",
                  workflow.type = "Aliquot Ensemble Somatic Variant Merging and Masking")
```

### 4.1 生存分析骨架

```r
library(survival); library(survminer)

dat <- merge(expr_t, clin, by = "barcode")   # 表达与临床按 barcode 合并，注意 barcode 截取长度一致
dat$group <- factor(ifelse(dat$GENE > median(dat$GENE), "High", "Low"))

fit <- survfit(Surv(os_time, os_event) ~ group, data = dat)
ggsurvplot(fit, pval = TRUE, risk.table = TRUE)

## 多因素校正（必须做，否则结论易被分期等因素解释）
cox <- coxph(Surv(os_time, os_event) ~ group + age + stage, data = dat)
summary(cox)
```

**三个统计红线**

1. **不要用"最佳截断值"分组**——它会系统性高估效应且难以重复；用中位数、四分位或临床预设阈值；
2. **必须做多因素校正**（年龄、性别、分期、治疗）；
3. **报告 HR 与 95% 置信区间**，而不是只报 P 值。

## 五、常见研究套路与"套路化"风险

最常见的组合是：**差异基因 → GO/KEGG 富集 → 生存分析 → 免疫浸润 → 列线图**。这套流程技术门槛低，也正因如此**同质化严重**，审稿人常见的质疑包括：

| 质疑 | 应对 |
| --- | --- |
| "都是公共数据，没有自己的验证" | 自有小队列做 qPCR/IHC 验证，或使用独立公共队列 |
| "循环验证" | 建模与验证数据集严格分开 |
| "截断值随意" | 使用预设或中位数分组，并做敏感性分析 |
| "富集结果无方向" | 区分上调/下调，或改用 GSEA |
| "没有临床问题" | 明确要回答的临床问题，而不是"跑完流程" |
| "结论过度" | 用"关联/提示"而非"驱动/导致" |

**提升说服力的三个做法**：① 引入**未在原文用过的分析角度**（如免疫浸润的空间/单细胞验证）；② 结合**自己医院的实际队列**；③ 把结果落到**可验证的假设或临床分层**上。

## 六、常见坑与排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 分组标签错乱 | 直接用列顺序指定分组 | 依据 pData 字段逐一样本核对，打印对照表 |
| log 转换判断错误 | 只看最大值不看分布 | 用分位数判断，论文写明依据 |
| 样本与临床对不上 | barcode 截取长度不一致 | 统一到一致长度（如 15 位），再合并 |
| 生存时间全是 NA | 临床字段名版本变化 | 先 `colnames(clin)` 查看实际字段 |
| 结果好得不像真的 | 建模数据被用于验证 | 严格区分发现与验证数据集 |
| 富集结果互相矛盾 | ORA 用阈值、GSEA 用全排序 | 同时报告，以 GSEA 为主解释趋势 |
| 不同数据集结论相反 | 平台、人群、预处理差异 | 分别报告并讨论原因，而非强行合并 |
| 免疫浸润结果与原文不符 | 方法不同（分数 vs 比例） | 统一方法并做一致性验证 → [[17 免疫浸润分析]] |
| 下载中断/文件损坏 | 网络或存储问题 | 校验文件大小与 md5，重下 |
| 磁盘被写满 | TCGA 数据量巨大 | 只下载需要的样本/文件，及时清理 |

## 七、自查清单

- [ ] 数据集编号、平台、数据类型、样本量是否全部记录？
- [ ] 分组标签是否逐一核对过来源？
- [ ] log 转换与归一化依据是否写明？
- [ ] 批次是否检查过、是否与分组混杂？
- [ ] 建模与验证数据集是否严格分开？
- [ ] 生存分析是否避免最佳截断值、是否多因素校正？
- [ ] 免疫浸润等推断结果是否做了方法一致性验证？
- [ ] 是否明确列出了数据使用条款与引用？
- [ ] 脚本与中间文件是否存档可复现？
