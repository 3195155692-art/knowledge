# 免疫浸润分析

> **一句话定位**：用**组织层面的表达谱**（芯片或 bulk RNA-seq）推断这块组织里有哪些免疫细胞、大概多少——它是"从平均值反推组成"，属于**统计推断**，不是直接测量。
> **三条必须记住的前提**：① 输出的是**相对比例或富集分数**，不是细胞计数；② 不同方法结果常有差异，**多方法一致才可信**；③ 它不能替代病理 TILs 评估或流式细胞术。

---

## 一、这项技术能回答什么问题

| 问题 | 免疫浸润分析能给出 | 不能给出 |
| --- | --- | --- |
| 这批肿瘤里免疫细胞多不多？ | 免疫细胞比例或免疫评分 | 细胞数量（个/mm²） |
| 哪类免疫细胞占主导？ | 各类细胞的相对占比 | 细胞的精确表型与功能状态 |
| 两组样本的免疫组成有差异吗？ | 组间比例比较（需正确统计） | 差异是"细胞变多"还是"其他细胞变少" |
| 免疫浸润与预后有关吗？ | 相关性/生存分析结果 | 因果关系 |
| 患者会不会对免疫治疗有反应？ | 与响应相关的趋势性证据 | 单个患者的用药决策依据 |
| 免疫细胞在肿瘤内还是边缘？ | 无法回答（需空间数据） | → 见 [[08 空间组学]] |

## 二、基本原理

### 2.1 为什么能从表达谱反推细胞组成

组织是多种细胞的混合物。如果一个基因只在某类免疫细胞里高表达，那么"这块组织里该基因表达高"就意味着"这类细胞可能比较多"。数学上把组织表达谱看作各细胞类型特征表达谱的**加权混合**：

**组织表达 ≈ Σ（细胞类型比例 × 该细胞类型的特征表达）**

去卷积就是反向求解这个方程，得到各类细胞的比例。参考矩阵（signature matrix）就是这个方程里"各类细胞的典型表达特征"。

### 2.2 三类主流方法

| 类别 | 代表方法 | 原理 | 输出含义 |
| --- | --- | --- | --- |
| **富集打分类** | ssGSEA、GSVA、xCell、MCP-counter | 用一组标志基因的整体表达水平打分 | 富集分数/丰度分数，**不是比例** |
| **矩阵去卷积类** | CIBERSORT、EPIC、quanTIseq、ImmuCellAI | 求解上述混合方程 | 相对比例（部分方法含总免疫分数） |
| **单细胞参考类** | CIBERSORTx（自定义矩阵）、MuSiC、BayesPrism、SCDC | 用单细胞数据构建更贴近本研究的参考矩阵 | 比例，参考依赖性强 |

另有一类**统一接口工具**（如 immunedeconv）把多种方法封装在一起，便于做一致性比较——**这是实际操作中推荐的做法**。

### 2.3 由此决定的三条判读规则

1. **比例数据是组成性数据。** 所有细胞类型的比例之和固定（常为 1），所以"某类细胞占比下降"可能只是其他细胞占比上升造成的，**不等于它绝对减少**。这直接影响统计方法的选择（见第 7 节）。
2. **输出的粒度取决于参考矩阵。** CIBERSORT 的 LM22 把免疫细胞分成 22 类，但"巨噬细胞 M1/M2"的区分在转录组层面本就不可靠——**参考矩阵的细胞定义决定了你结论的天花板**。
3. **模型假设不成立时结果无意义。** 去卷积假设"各细胞类型的表达特征在样本间稳定"，但肿瘤细胞本身会表达免疫相关基因、组织来源与平台不同都会打破这个假设。

## 三、方法怎么选

| 场景 | 推荐方法 | 理由 |
| --- | --- | --- |
| 芯片 + bulk RNA-seq 混合队列 | CIBERSORT、MCP-counter、quanTIseq | 对平台差异相对稳健 |
| 只想看"免疫活性高低" | ssGSEA/GSVA + ESTIMATE | 简单、易解释 |
| 需要各细胞类型的相对比例 | CIBERSORT、quanTIseq、EPIC | 输出比例，便于做堆叠图 |
| 想同时看肿瘤纯度 | ESTIMATE、quanTIseq、EPIC | 输出纯度或总免疫分数 |
| 有本课题单细胞数据 | CIBERSORTx 自定义矩阵、MuSiC、BayesPrism | 参考矩阵更贴合样本 |
| 需要多方法相互验证 | immunedeconv 统一调用 | 一致性分析是可靠性前提 |
| 关注免疫治疗响应预测 | TIDE、Immunophenoscore | 属预测工具，**验证证据有限** |

**选型原则**：先用 2–3 种原理不同的方法（如 CIBERSORT + MCP-counter + ssGSEA）跑同一批数据，**只报告多方法一致的结果**。

## 四、数据准备（决定结果能不能用）

### 4.1 表达矩阵的四个要求

1. **数值要在线性空间**。CIBERSORT 一类方法要求使用**非 log 转换**的 TPM/FPKM 或芯片归一化后的线性值；把 log2 数据直接送进去会得到系统性错误结果。
2. **基因标识要统一且去重**。基因名与 Ensembl ID 混用、一个基因多个 ID 或一 ID 多基因，都会导致标志基因丢失；转换后需聚合并去重。
3. **样本层面要做质控**。低质量样本、批次效应、肿瘤纯度差异都会污染结果；建议先做批校正与离群样本排查（见 [[15 转录组分析实操]]）。
4. **全库样本一起处理**。不同研究、不同平台的矩阵**不能直接把比例结果放在一起比较**；跨数据集比较必须重新统一处理。

### 4.2 参考矩阵的适用性检查

| 检查项 | 说明 |
| --- | --- |
| 组织类型 | 参考矩阵多基于血液/肿瘤样本，用于脑、肝等特殊组织时准确性下降 |
| 细胞类型定义 | 是否包含你关心的亚型（M1/M2、Treg、耗竭 T 细胞等） |
| 平台匹配 | 芯片与 RNA-seq 的基因覆盖与动态范围不同 |
| 是否有该癌种的验证 | 部分方法在特定癌种做过验证，应优先选用 |

### 4.3 分析前必须问清楚的五个问题

1. 我的矩阵在线性空间吗？基因 ID 是否已统一去重？
2. 我关心的是"免疫活性"还是"具体细胞比例"？（决定选富集类还是去卷积类）
3. 参考矩阵是否适合我的组织类型和平台？
4. 我要用几种方法做一致性验证？
5. 结果打算怎么用于临床结论？能否被病理或流式数据支持？

## 五、输入输出与文件格式

| 文件 | 内容 | 说明 |
| --- | --- | --- |
| 表达矩阵（TSV/CSV） | 基因 × 样本 | 线性空间、基因名或 Ensembl ID 单列 |
| 参考矩阵 | 细胞类型 × 基因 | 如 LM22，需与表达矩阵基因标识一致 |
| 比例结果表 | 样本 × 细胞类型 | CIBERSORT 输出含 P 值、相关性、RMSE |
| 打分结果表 | 样本 × 细胞/通路 | ssGSEA、xCell、MCP-counter 输出 |
| 可视化文件 | 堆叠柱状图、箱线图、热图、森林图 | 交付与投稿用 |

## 六、标准分析流程（含代码骨架）

```
表达矩阵（线性空间）
  ↓ ① 基因标识统一与去重
  ↓ ② 样本质控（离群样本、批次）
  ↓ ③ 选择 2–3 种方法并行运行（immunedeconv 统一接口）
  ↓ ④ 结果一致性比较（相关性与方向性）
  ↓ ⑤ 统计检验（构成性数据专用方法）
  ↓ ⑥ 与临床变量/预后的关联分析
  ↓ ⑦ 可视化与结果汇总
  ↓ ⑧ 独立队列验证（公共数据或自有队列）
```

### 6.1 R 代码骨架（统一接口方式）

```r
# 依赖：immunedeconv（统一封装 CIBERSORT、MCP-counter、xCell、EPIC、quanTIseq 等）
library(immunedeconv); library(tidyverse)

expr <- as.matrix(read.delim("expr_linear.tsv", row.names = 1, check.names = FALSE))
expr <- expr[rowSums(expr) > 0, , drop = FALSE]   # 去空行，注意不要对 TPM 再做 log

res_cibersort <- deconvolute(expr, method = "cibersort")            # 相对比例
res_mcp       <- deconvolute(expr, method = "mcp_counter")          # 丰度分数
res_quantiseq <- deconvolute(expr, method = "quantiseq")            # 比例 + 总免疫分数
res_epic      <- deconvolute(expr, method = "epic")                 # 含肿瘤细胞比例

# 一致性比较：不同方法对同一细胞类型的相关性
cor(as.numeric(res_cibersort[res_cibersort$cell_type == "T cell CD8+", -1]),
    as.numeric(res_mcp[res_mcp$cell_type == "CD8+ T cell", -1]))
```

### 6.2 ssGSEA / GSVA 打分骨架

```r
library(GSVA); library(GSEABase)
gene_sets <- list(
  `CD8+ T cell` = c("CD8A","CD8B","GZMK"),
  `Cytotoxic`   = c("GZMA","PRF1","GZMB"),
  `Treg`        = c("FOXP3","IL2RA","CTLA4"),
  `M1-like`     = c("NOS2","IL1B","TNF"),
  `M2-like`     = c("CD163","MSR1","MRC1")
)
scores <- gsva(as.matrix(log2(expr + 1)), gene_sets, method = "ssgsea")
```

> 注意：**去卷积用线性值，打分类方法常接受 log 值**，两者要求不同，混用要看清文档。

### 6.3 结果一致性检查

1. 计算不同方法对**同一细胞类型**的相关系数（一般 0.5–0.9）；
2. 检查**组间方向**是否一致（两组高低关系不能相互矛盾）；
3. 对矛盾的细胞类型，**不报告为结论**，或改用更匹配的方法/单细胞参考矩阵重算。

## 七、质量控制与统计要点

### 7.1 必须检查的技术指标

| 指标 | 参考 | 异常含义 |
| --- | --- | --- |
| CIBERSORT 的 P 值（deconvolution P） | 建议 <0.05 才纳入后续分析 | 说明混合信号无法被参考矩阵解释 |
| 相关性（Correlation）与 RMSE | 输出中给出 | 拟合质量差则比例不可信 |
| 单样本比例异常 | 某类细胞 >80% 或全为 0 | 提示数据或参考矩阵不匹配 |
| 不同方法一致性 | 方向一致、相关中等以上 | 不一致则结论不可靠 |
| 与肿瘤纯度的关系 | 纯度低时免疫比例失真 | 需校正或纳入协变量 |
| 批次与平台 | 应与分组解耦 | 混杂则无法区分 |

### 7.2 统计方法：不要用普通 t 检验

免疫细胞比例是**组成性数据**（总和固定），直接做 t 检验或相关分析会产生虚假结果。可行做法：

1. **中心化对数比（CLR）转换**后再做检验；
2. 或用专门处理组成性数据的方法（如 09 篇提到的 ANCOM-BC 类思路）；
3. 报告时说明使用的转换与检验方法；
4. 多重检验校正（细胞类型数量多时必然需要）。

### 7.3 生存分析要点

- 免疫浸润与预后的分析常用"高/低浸润"分组：**不要用最佳截断值**，优先使用中位数或预设阈值，并说明理由；
- 单因素分析必须再做多因素校正（分期、年龄、治疗）；
- 比例类指标建议以**连续变量**进入 Cox 模型，而不是人为二分。

## 八、结果怎么读（临床视角）

### 8.1 先问"这结果和病理对不对得上"

如果分析显示"CD8+ T 细胞极高浸润"，而病理报告描述为"淋巴细胞稀疏"，那么**优先怀疑分析问题**（数据、参考矩阵、基因标识或样本标签）。生信推断与病理观察不一致时，不要默认生信是对的。

### 8.2 三个容易过度解读的结论

| 常见表述 | 问题 | 更稳妥的表述 |
| --- | --- | --- |
| "该亚型 CD8+ T 细胞显著增多" | 比例变化可能来自其他细胞减少 | "CD8+ T 细胞相对占比更高" |
| "免疫浸润高提示预后好" | 方向**依癌种而定**，且未校正混杂 | 需说明癌种、队列与校正因素 |
| "免疫浸润高，适合免疫治疗" | 浸润 ≠ 响应；需 TMB/MSI/PD-L1 等综合判断 | 表述为"关联趋势，需进一步证据" |

### 8.3 与病理 TILs 评估的关系

病理 TILs 评估有国际工作组标准，评估的是**实际细胞与空间分布**（基质内/瘤内），是当前临床与临床试验中最被接受的免疫评估方式；生信免疫浸润是**整体推断**，两者互补但不等价。论文中若同时报告两者且结论一致，说服力显著提高。

### 8.4 与免疫治疗标志物的关系

临床上用于免疫治疗决策的标志物是 PD-L1 免疫组化、MSI/dMMR、TMB 等**经过前瞻性验证的指标**；免疫浸润推断（包括 TIDE、Immunophenoscore 类预测工具）主要属于**研究性证据**，不应直接用单个患者的用药决策 → 参见 [[01 基因组学]] 与 [[11 临床研究设计与统计要点]]。

## 九、临床应用与研究场景

### 9.1 预后分层研究

免疫浸润与预后的关系具有**癌种依赖性**：在结直肠癌等癌种中，Th1/细胞毒性 T 细胞高浸润与更好预后相关（这也是"免疫评分"概念的基础）；但在部分癌种中，某些免疫细胞群与不良预后相关。**不能跨癌种套用结论。**

### 9.2 免疫治疗响应研究

常用于解释治疗响应的机制、寻找联合治疗靶点、或构建预测模型。要点：**必须用独立队列验证**，并报告增量价值（相比 TMB/PD-L1 等已有指标是否更好）。

### 9.3 分子分型与免疫分型

泛癌免疫分型（如把肿瘤分为若干免疫亚型）是这一方向的代表性成果，可用于解释不同癌种或同一癌种内的免疫状态差异。

### 9.4 与单细胞、空间数据的联合

最规范的做法是：**单细胞数据定义细胞类型 → 空间数据确认位置 → bulk 去卷积扩展到大队列**。只有 bulk 推断而没有细胞层面证据时，结论强度有限 → [[04 单细胞分析]]、[[08 空间组学]]。

## 十、局限与常见陷阱

| 陷阱 | 错在哪 | 怎么避免 |
| --- | --- | --- |
| 用 log 值跑 CIBERSORT | 违反方法前提，结果全错 | 先确认矩阵是否在线性空间 |
| 把分数当比例 | 富集分数与细胞比例含义不同 | 明确方法输出定义 |
| 只用一种方法就下结论 | 方法间差异大 | 2–3 种方法一致性验证 |
| 用 t 检验比较比例 | 组成性数据假设不成立 | CLR 转换或专用方法 |
| 忽略肿瘤纯度 | 纯度低导致比例失真 | 用 EPIC/quanTIseq 估计并校正 |
| 用最佳截断值分组做生存分析 | 高估效应、无法重复 | 中位数/预设阈值 + 多因素校正 |
| 跨平台/跨数据集直接比较 | 系统性差异被当生物学差异 | 统一处理后再比较 |
| 把 M1/M2 当可靠分类 | 转录组层面难以区分 | 报告为"巨噬细胞"或使用更粗的分类 |
| 单队列结论当成定论 | 无法重复 | 独立队列验证 |
| 与病理结果矛盾却不解释 | 数据可信度存疑 | 回查数据与标签，如实报告 |
| 用推断结果指导单个患者治疗 | 证据等级不足 | 以病理、PD-L1、MSI、TMB 为准 |
| 忽略样本量 | 结果不稳定 | 事先估算样本量 |
