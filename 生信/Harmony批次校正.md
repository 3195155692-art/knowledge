## 一、先搞清楚：Harmony 在单细胞分析里干嘛用？

**场景**：你的 GBM 单细胞实验有 8 个样本（对照组 4 只、治疗组 4 只），分两次上机、可能还涉及不同试剂批次。画 UMAP 时发现：同一类细胞（比如巨噬细胞）没有聚成一团，而是**按样本/批次分成了几小堆**。

这就是**批次效应（batch effect）**：由技术因素（上机时间、试剂、建库、操作者、测序深度）造成的、与真实生物学无关的系统差异。

Harmony 是一个快速、流行的**批次校正（batch correction）/ 整合**算法，在 PCA 空间把不同批次的同类细胞"对齐"，让它们在后续 UMAP 和聚类里正确地聚到一起，而不是被技术差异人为分开。

流程位置：

```
PCA → 【Harmony 批次校正】→ 用 harmony 嵌入做聚类和 UMAP
```

---

## 二、为什么必须处理批次效应？

### 1. 不校正会得到假的"细胞类型"

聚类可能把"对照组的巨噬细胞"和"治疗组的巨噬细胞"错分成两个簇，你会误以为发现了新细胞类型，其实只是批次差异。

### 2. 干扰组间比较

你想比较治疗前后的差异，批次如果和分组混杂（比如对照组全在第一次上机、治疗组全在第二次），根本分不清差异来自治疗还是技术。

### 3. 影响下游一切

邻居、聚类、UMAP、差异分析都建立在降维结果上，批次不除，错误层层传递。

### 但要警惕过度校正

批次校正不是"把所有差异都抹平"。真实的生物学差异（治疗确实改变了细胞状态）必须保留，只去掉技术差异。这是 Harmony 使用的核心难点。

---

## 三、核心原理：软聚类 + 迭代对齐

### 直觉：多份卷子统一阅卷标准

想象不同批次像几个班级，同一水平的学生在不同老师手里打分标准不一。Harmony 做的是：先识别"哪些学生其实是同一水平"（不管在哪个班），再把各班的打分标准校准到统一尺度，但不改变学生之间真实的水平差距。

### 第 1 步：在 PCA 空间做软聚类

Harmony 不把每个细胞硬分到某一类，而是**软聚类（soft clustering）**：一个细胞可以按概率同时属于多个簇。比如某细胞 70% 像簇 A、30% 像簇 B。

### 第 2 步：计算每个批次在每个簇上的"偏移"

对每个簇，比较不同批次的细胞中心位置，算出各批次相对整体中心的偏移量（这就是批次造成的系统偏差）。

### 第 3 步：减去批次偏移、迭代

把每个细胞朝"消除本批次偏移"的方向校正，然后重新聚类、重新算偏移，反复迭代直到收敛。

### 软聚类为什么用"软"而不是"硬"

用比喻：硬聚类像把每个人强制贴一个标签，边界上的细胞容易被贴错；软聚类像允许"我既像 A 又像 B"，边界细胞在多个簇间分摊，校正更平滑、不容易把稀有类型错误地拉向大簇。

### 关键参数

| 参数 | 含义 | 影响 |
|---|---|---|
| `group.by.vars` | 按哪个变量校正（批次、样本） | 可同时校正多个变量 |
| `theta` | 校正强度 | 越大校正越激进，太大易过度校正 |
| `lambda` | 校正的收缩程度 | 越大校正越温和 |
| `max.iter` | 迭代次数 | 控制收敛 |

## 四、迷你图解：看一次"对齐"

假设只有 2 个批次、1 个细胞类型，在 PC1 上的位置：

```
校正前：
批次1 的细胞中心：  PC1 = -2
批次2 的细胞中心：  PC1 = +2
（同类细胞被批次拉开）
```

Harmony 算出整体中心在 0，批次 1 偏移 -2、批次 2 偏移 +2，于是：

```
批次1 细胞 +2、批次2 细胞 -2
校正后两批中心都到 0，同类细胞重合
```

如果两个批次里本来就有"肿瘤细胞"和"免疫细胞"两类，Harmony 会分别在各自的簇内对齐，而不会把两类细胞错误地合并——这正是软聚类分簇后再校正的作用。

## 五、Harmony vs 其他整合方法

| 方法 | 空间/思路 | 速度 | 特点 | 适用 |
|---|---|---|---|---|
| Harmony | PCA 空间、软聚类迭代 | 很快 | 轻量、保留生物差异较好 | 多样本、大规模 |
| Seurat CCA/锚点 | 典型相关分析、找锚点 | 中等 | 经典、跨条件整合强 | 差异较大的数据集 |
| BBKNN | 邻居图对齐 | 很快 | 简单、直接改邻居 | 快速整合 |
| scVI | 深度生成模型 | 慢（需 GPU） | 建模复杂、可扩到多组学 | 大数据、复杂设计 |
| LIGER/iNMF | 联合非负矩阵分解 | 中等 | 保留数据集特异信号 | 跨物种/跨模态 |

**选择原则**：批次差异温和、样本量大、追求速度和保留生物差异 → Harmony 通常是首选；数据集之间生物学差异很大、需要更强整合 → 考虑锚点/scVI。

## 六、代码（R / Seurat + Python）

```r
library(harmony); library(Seurat)
obj <- RunPCA(obj, npcs = 50)
# 在 PCA 空间按批次校正
obj <- RunHarmony(obj, group.by.vars = "batch", theta = 2, lambda = 1)

# 下游全部改用 harmony 嵌入
obj <- FindNeighbors(obj, reduction = "harmony", dims = 1:20) |>
  FindClusters(resolution = 0.6) |>
  RunUMAP(reduction = "harmony", dims = 1:20)

# 校正前后对比
DimPlot(obj, reduction = "pca", group.by = "batch")
DimPlot(obj, reduction = "umap", group.by = "batch")
```

同时校正多个变量（如批次 + 供体）：

```r
obj <- RunHarmony(obj, group.by.vars = c("batch", "donor"))
```

Python（scanpy + harmonypy）：

```python
import scanpy as sc
from harmonypy import run_harmony
sc.tl.pca(adata)
ho = run_harmony(adata.obsm['X_pca'], adata.obs, 'batch')
adata.obsm['X_harmony'] = ho.Z_corr.T
sc.pp.neighbors(adata, use_rep='X_harmony')
sc.tl.umap(adata)
```

## 七、论文里怎么写

**方法**：

> 为消除不同建库批次导致的技术差异，在 PCA 嵌入上使用 Harmony（group.by.vars=batch，theta=2）进行批次校正。校正后的 Harmony 嵌入用于 KNN 图构建、聚类及 UMAP。通过比较校正前后按批次着色的 UMAP 评估整合效果。

**结果**：

> 校正前细胞主要按批次分离，Harmony 校正后同一细胞类型在不同批次间充分混合，且主要细胞类型仍保持清晰分离，提示批次效应被有效去除而生物学结构得以保留。

## 八、最常见的坑

1. **过度校正，抹掉真实生物学差异。**
   theta 过大、或把"分组/治疗"也当批次校正，会把治疗效应一起消除。只校正技术变量，校正后检查细胞类型是否仍可分。

2. **批次与分组完全混杂。**
   设计上让对照组全在一批、治疗组全在另一批，任何算法都无法区分技术与生物差异。实验设计阶段就要让各组分布在不同批次。

3. **不验证校正效果。**
   校正前后都要按批次和细胞类型着色对比，确认"批次混合、类型分离"。

4. **下游还在用 pca 而不是 harmony。**
   跑了 Harmony 却在 FindNeighbors/UMAP 里用 reduction="pca"，等于白做。

5. **把 Harmony 当差异分析。**
   它只做整合，组间差异表达要在校正后用 pseudobulk + DESeq2/edgeR 单独做。

6. **对差异极大的数据集强行用 Harmony。**
   跨物种、跨模态等强异质场景可能整合不足，应选 iNMF/scVI 等更合适的方法。

## 九、判断清单

用 Harmony 前问：

1. 是否确实存在多个批次/样本、且 UMAP 上看到按批次分离？
2. 要校正的变量是**技术批次**，而不是治疗分组？
3. 实验设计里批次和分组是否没有完全混杂？
4. theta/lambda 是否取合理值、避免过度校正？
5. 下游是否统一改用 harmony 嵌入？
6. 校正后是否检查"批次混合、生物类型仍分离"？

**一句话总结**：Harmony 在 PCA 空间通过软聚类识别跨批次的同类细胞，迭代地减去各批次的系统偏移，把不同批次的同类细胞对齐，同时尽量保留真实生物学差异；它快速、轻量，是多样本单细胞整合的常用首选，但必须只校正技术变量、严防过度校正，并在下游统一使用校正后的嵌入。
