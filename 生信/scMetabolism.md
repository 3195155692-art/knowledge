## 一、先搞清楚：scMetabolism 在单细胞分析里干嘛用？

**场景**：你已知 GBM 微环境里不同细胞类型的身份，现在想知道它们的**代谢状态**差异。比如：
- 肿瘤细胞是不是高度依赖糖酵解（Warburg 效应）？
- 哪群巨噬细胞的氧化磷酸化、脂质代谢更活跃？
- 治疗后肿瘤细胞的代谢通路活性有没有被抑制？

scMetabolism 是一个 R 包，从单细胞转录组数据出发，给每个细胞、每条代谢通路打一个**活性分数**，从而在单细胞分辨率上量化糖酵解、氧化磷酸化、三羧酸循环、氨基酸代谢、脂质代谢等数十条通路的活跃程度，并支持组间比较。

它本质是把"基因集富集打分"专门应用到代谢通路上。

---

## 二、为什么需要单细胞代谢分析？

### 1. 代谢是肿瘤的核心特征，但传统方法做不到单细胞分辨率

质谱、Seahorse 能量代谢仪能测代谢物/耗氧，但通常是**整块组织或一群细胞的平均**，看不到微环境里不同细胞、甚至同类细胞不同状态的代谢异质性。

### 2. 转录组可以间接推断代谢

虽然测的是 mRNA 不是代谢物，但某条代谢通路的酶基因普遍高表达，通常提示该通路活跃。单细胞转录组恰好提供了每个细胞的酶基因表达。

### 3. 服务机制和治疗

肿瘤细胞的代谢重编程、免疫细胞的代谢状态（如促炎/抗炎巨噬细胞的代谢差异）是机制和靶点研究的重要线索。

## 三、核心原理：基因集富集打分

### 直觉：看食材清单推断厨房在做什么菜

你没法直接看到锅里的菜（直接测代谢物很难），但能看到厨房备了哪些食材（酶基因的表达）。如果某道菜所需的食材备齐了、且量很大，就推断这道菜正在大量制作。

- 代谢通路 = 一道菜
- 通路上的酶基因 = 这道菜需要的食材
- 这些酶基因在细胞里高表达 = 食材备得多 → 推断通路活跃

### 第 1 步：代谢通路基因集

scMetabolism 内置从 KEGG、Reactome 等整理的代谢通路基因集，每条通路对应一组酶/相关基因。

### 第 2 步：对每个细胞做富集打分

支持多种打分算法（ssGSEA、VISION、AUCell、GSVA 等），共同思路是：**比较"通路内基因"相对"其余基因"的表达排名/水平**，输出一个分数。

以 ssGSEA 的直觉：在一个细胞内把所有基因按表达从高到低排队，看某条通路的基因是集中排在前面（→高分、活跃）还是散落在后面（→低分、不活跃）。

### 第 3 步：分数用于比较

得到"细胞 × 通路"的分数矩阵，可在 UMAP 上画分数、按细胞类型/分组比较。

## 四、迷你图解：理解富集打分

不做复杂计算，用一个细胞、一条通路理解。

某细胞里 8 个基因按表达从高到低排名：

```
排名：1    2    3    4    5    6    7    8
基因：G1   G2   G3   G4   G5   G6   G7   G8
某通路基因：  ✓        ✓             ✓
```

- 若该通路的基因（G2、G4、G7）整体排名靠前 → 通路得分高，判断"活跃"
- 若同样这几个基因整体排在末尾 → 得分低，判断"不活跃"

**关键直觉**：打分看的是"通路基因在细胞内的相对排名"，而不是某一个基因的绝对表达，因此比只看单个酶基因更稳健。

---

## 五、几种打分算法的区别

| 算法 | 思路 | 特点 |
|---|---|---|
| ssGSEA | 通路基因在表达排名上的累积分布差 | 常用、对表达量加权 |
| VISION | 基于签名的排名打分 | 快、适合大数据 |
| AUCell | 看高表达基因中通路基因占比（曲线下面积） | 对"是否开启"敏感、抗 dropout |
| GSVA | 跨样本的核密度富集 | 经典、更适合组间比较 |
| AddModuleScore（Seurat） | 通路基因均值减背景基因均值 | 简单、Seurat 自带 |

**选择原则**：常规单细胞代谢定量，scMetabolism 默认的 ssGSEA/VISION 即可；数据稀疏、dropout 严重可试 AUCell；结论最好用两种打分交叉验证。

---

## 六、scMetabolism vs 其他代谢分析方式

| 方式 | 分辨率 | 测的是 | 局限 |
|---|---|---|---|
| scMetabolism | 单细胞 | 通路酶基因表达推断 | 间接、非真实代谢物 |
| 质谱代谢组 | 组织/细胞群 | 真实代谢物 | 难单细胞、需专门样本 |
| Seahorse | 细胞群 | 耗氧/产酸（能量流） | 通量低、不分细胞类型 |
| 空间代谢组 | 空间区域 | 代谢物空间分布 | 分辨率/覆盖有限 |
| Compass/COMPASS | 单细胞 | 通量平衡模型更细 | 计算重 |

**定位**：scMetabolism 是"低成本、单细胞、间接推断"的筛选工具，关键结论要用代谢组或功能实验确认。

## 七、代码（R / scMetabolism）

```r
library(scMetabolism)
library(Seurat)
# 输入 Seurat 对象（建议先标准化）
countexp <- sc.metabolism(
  obj,
  method = "ssgsea",          # 可选 vision/aucell/gsva
  metabolism.type = "KEGG",   # 或 Reactome
  imputation = FALSE
)
# countexp@meta 是 细胞 × 通路 的分数矩阵
metabolism <- countexp@meta
```

可视化：

```r
# UMAP 上画某条通路分数
DimPlot.metabolism(obj, countexp, pathway = "Glycolysis",
                   dimention.reduction.type = "umap")
# 箱线图比较不同细胞类型
DotPlot.metabolism(obj, countexp,
                   pathway = c("Glycolysis", "Oxidative phosphorylation"),
                   phenotype = "celltype")
```

Seurat 自带的模块打分（不依赖该包）：

```r
obj <- AddModuleScore(obj, features = list(glycolysis_genes),
                      name = "glycolysis")
```

## 八、论文里怎么写

**方法**：

> 为在单细胞分辨率评估代谢状态，使用 scMetabolism（KEGG 代谢通路基因集，ssGSEA 算法）对每个细胞计算各代谢通路活性分数。比较不同细胞类型及对照组/治疗组间的通路分数（Wilcoxon 检验，BH 校正）。

**结果**：

> 肿瘤细胞的糖酵解通路分数显著高于其他细胞类型（中位数 a vs b，调整后 P<0.01），而治疗组肿瘤细胞糖酵解分数较对照组下降，提示治疗抑制了其糖酵解代谢重编程。

## 九、最常见的坑

1. **把 mRNA 分数当真实代谢通量。**
   转录后调控、酶活性、底物可获得性都会让"酶基因高表达"不等于"代谢真的快"。需代谢组/Seahorse 验证。

2. **基因集质量不检查。**
   不同数据库（KEGG/Reactome）对通路定义不同，结果会有差异；要注明来源、必要时交叉验证。

3. **dropout 导致低估。**
   单细胞数据稀疏，低表达酶基因容易漏检，可结合 AUCell 或插补并谨慎解读。

4. **不做背景/归一化直接比。**
   不同细胞测序深度、总表达不同，打分和组间比较要基于标准化数据。

5. **只靠一种算法下结论。**
   ssGSEA、AUCell、GSVA 结果可能不一致，关键通路用两种以上方法印证。

6. **把通路分数当连续可精确测量值。**
   它是相对排名分数，适合比较高低，不宜解释成具体代谢物浓度或反应速率。

7. **忽略细胞类型/状态混杂。**
   比较组间代谢时要控制细胞组成，避免"细胞比例变化"被误读成"代谢改变"。

## 十、判断清单

用 scMetabolism 前问：

1. 目标是不是在单细胞层面**间接**比较代谢通路活性？
2. 数据是否已标准化、稀疏程度如何？
3. 用哪套基因集、哪种打分算法，是否计划交叉验证？
4. 组间比较是否控制了细胞类型/比例混杂？
5. 关键结论是否安排了代谢组或功能实验验证？
6. 是否避免把分数表述成真实代谢物浓度？

**一句话总结**：scMetabolism 用基因集富集（如 ssGSEA）给每个细胞的每条代谢通路打活性分，基于"通路酶基因的相对表达排名"间接推断代谢状态，能在单细胞分辨率揭示肿瘤糖酵解、免疫细胞代谢等异质性并比较治疗前后变化；但它测的是 mRNA 而非真实代谢通量，属于低成本筛选工具，重要结论必须用代谢组或功能实验确认。
